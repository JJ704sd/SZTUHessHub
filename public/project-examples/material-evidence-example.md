## 1. 用途、输入与必要约束

练习问题：在一组预设参数下，把“性能、费用、吸水”三种偏好写成能复算的矩阵，并观察改变权重会不会改变首选？

- 输入来源：编辑手工构造的参数表；按 CC BY 4.0 提供。没有供应商规格、采购报价或实测依据。
- 输入版本：本文件的 2026-10-03 版本。
- 编辑完成：约束设定、归一化、两组权重和排序复算。未完成：材料制备、样品检测、真实成本与环境条件核验。
- 执行环境：下方无依赖 JavaScript 可在 Node.js 中运行；本轮算数复核使用 Node.js v24.14.1。
- 合成必要约束：模量不低于 50 MPa，费用不高于 200 元/件，吸水率不高于 8%。三者同时满足才进入评分。它们不是行业门槛。

| 候选 | 示意模量 E（MPa） | 示意费用 C（元/件） | 示意吸水率 W（%） | 必要约束 |

| A | 60 | 100 | 4 | 全部通过 |
| B | 80 | 180 | 2 | 全部通过 |
| C | 100 | 140 | 6 | 全部通过 |

这里的单位只用于演示如何保留量纲，不意味着这些参数已经在同一真实测试条件下测得。

## 2. 统一到 0—1 的分数

本例预设模量越大越好，费用和吸水率越小越好。实际问题应先确认优劣方向；某些指标可能是接近目标值更好，不能直接照搬本例。

- 越大越好：`s = (x - min) / (max - min)`。
- 越小越好：`s = (max - x) / (max - min)`。
- `min`、`max` 取本轮通过必要约束的 3 个候选；排序只对这一候选集合成立。
- 本例没有缺失值，也没有同一指标所有候选都相等的情况。换成自己的数据时，必须先规定这些情况的处理方式，不能把缺失项填 0 充数。

| 候选 | 模量分数（越大越好） | 费用分数（越小越好） | 吸水分数（越小越好） |
| --- | ---: | ---: | ---: |
| A | (60−60)/40 = 0 | (180−100)/80 = 1 | (6−4)/4 = 0.5 |
| B | (80−60)/40 = 0.5 | (180−180)/80 = 0 | (6−2)/4 = 1 |
| C | (100−60)/40 = 1 | (180−140)/80 = 0.5 | (6−6)/4 = 0 |

## 3. 两组权重与实际算数结果

综合分数为 `模量权重 × 模量分数 + 费用权重 × 费用分数 + 吸水权重 × 吸水分数`。

| 偏好组 | 模量权重 | 费用权重 | 吸水权重 | 权重总和 | 解释 |
| --- | ---: | ---: | ---: | ---: | --- |
| 组一 | 0.40 | 0.35 | 0.25 | 1.00 | 同时考虑三项，略偏重模量 |
| 组二 | 0.20 | 0.20 | 0.60 | 1.00 | 更关注较低的吸水率 |

权重是编辑为比较而设的偏好，不来自真实需求访谈或专业标准。

| 候选 | 组一分数 | 组一排名 | 组二分数 | 组二排名 |
| --- | ---: | ---: | ---: | ---: |
| A | 0.475 | 2 | 0.500 | 2 |
| B | 0.450 | 3 | 0.700 | 1 |
| C | 0.575 | 1 | 0.300 | 3 |

例如 A 的组一分数：`0.40 × 0 + 0.35 × 1 + 0.25 × 0.5 = 0.475`；B 的组二分数：`0.20 × 0.5 + 0.20 × 0 + 0.60 × 1 = 0.700`。

组一排序为 **C > A > B**，组二排序为 **B > A > C**。B 的吸水分数最高，吸水权重增加后从第三变为第一。这说明首选依赖偏好，不能把 C 或 B 单独写成“最优材料”。

### 自己复算一次

保存下面代码为 `verify-material.mjs`，运行 `node verify-material.mjs`。计算保留原值，输出时才保留三位小数。

```js
const candidates = [
  { id: 'A', values: [60, 100, 4] },
  { id: 'B', values: [80, 180, 2] },
  { id: 'C', values: [100, 140, 6] },
];
const directions = ['higher', 'lower', 'lower'];
const eligible = candidates.filter(({ values: [e, c, w] }) =>
  e >= 50 && c <= 200 && w <= 8
);
const normalized = eligible.map(candidate => ({
  id: candidate.id,
  scores: candidate.values.map((value, i) => {
    const column = eligible.map(row => row.values[i]);
    const min = Math.min(...column);
    const max = Math.max(...column);
    return directions[i] === 'higher'
      ? (value - min) / (max - min)
      : (max - value) / (max - min);
  }),
}));
for (const weights of [[0.40, 0.35, 0.25], [0.20, 0.20, 0.60]]) {
  const weightSum = weights.reduce((sum, value) => sum + value, 0);
  const results = normalized.map(({ id, scores }) => ({
    id,
    score: scores.reduce((sum, value, i) => sum + value * weights[i], 0),
  })).sort((a, b) => b.score - a.score);
  console.log({ weightSum, ranking: results.map(row =>
    `${row.id}: ${row.score.toFixed(3)}`
  ) });
}
```

这段代码只面向上面的完整合成表。它没有定义缺失值、同值列和并列排名的处理策略，不应直接当成通用选型工具。

## 4. 下一步与局限

本轮实际完成的是给定数字的加权计算和一次权重敏感性比较。尚未比较测量误差、温度或湿度条件变化，也没有验证必要约束的合理性。若新增候选导致最小/最大值变化，旧候选的归一化分数也会变化，需要整体重算。

第一步应补的是每项参数在什么条件下得到，以及哪些约束是必须满足的。再讨论权重如何由真实使用任务确定，而不是通过不断调权重让喜欢的候选得第一。

## 5. 换成自己的记录与交接

1. 写下实际用途和必要约束；参数来自文献、规格或实测时，记录出处、日期、许可、单位和条件。
2. 明确每项优劣方向及缺失值处理；先做约束筛选，再归一化。
3. 保留两组有理由的权重、每个候选的展开算式和排序；对同分另写判定规则。
4. 交付参数原表、公式/脚本、计算结果及限制说明。让同伴独立复算一个候选，不只检查最终名次。
