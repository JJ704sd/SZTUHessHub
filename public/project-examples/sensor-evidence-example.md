## 1. 系统与输入

练习问题：接收一个合成数值时，界面如何区分正常、异常、断开和手动停止，并避免把旧值当成新读数？

- 输入来源：编辑手工指定的无量纲数值，不对应人体、真实传感器或医疗指标。
- 输入许可：本文的合成输入和原创规则按 CC BY 4.0 提供；替换外部程序或数据时另行记录其许可。
- 范围：纯软件仿真规划；不接入人体、市电、真实医疗设备或生产系统。
- 计划采样间隔：每 1 秒一次。`connected` 表示连接标记；`value` 为数值或 `null`；`stop` 是手动停止指令。
- 编辑完成：输入约定、状态优先级与测试计划。未完成：仿真实现、硬件连接、日志采集和实际执行。
- 执行环境：未建立；工具版本、启动命令和日志路径均待实际实施时填写。

## 2. 可以逐条读懂的状态规则

初始状态为“等待输入”。每次处理先按以下优先级判断，命中一条后不再判断后面的条目：

1. **手动停止**：收到 `stop = true`，进入停止状态并锁定。停止后忽略后续采样输入，显示“已手动停止”，清空当前值，不再产生正常/异常提示。只有显式重新开始一轮运行才解除锁定。
2. **断开**：尚未停止，且 `connected = false` 或 `value = null`，显示“输入断开”，清空当前值；保持等待新输入，不能展示旧值作为当前值。重新收到连接正常且数值有效的输入后重新判断。
3. **异常**：尚未停止、连接正常且数值有效，但 `value < 20` 或 `value > 80`，显示“超出练习范围”与当前值，继续监测。异常本身不触发手动停止锁定。
4. **正常**：其余有效数值，即 `20 <= value <= 80`，显示“输入正常”与当前值，继续监测。

本例只约定有限数值或 `null`；其他格式不是本轮用例的已覆盖输入。实际实现若需要接收字符串、`NaN` 或无穷大，应先明确输入契约并补对应测试。

## 3. 四类核心用例

每行从新的一轮“等待输入”开始，互不继承停止状态。`stop = false` 表示未按停止键。

| 用例 | 输入 | 预期状态 | 预期提示与当前值 | 预期是否继续采样 | 实际执行 / 证据 |
| --- | --- | --- | --- | --- | --- |
| 正常 N1 | connected=true, value=50, stop=false | 正常 | 输入正常；当前值 50 | 是 | 未执行；无日志 |
| 异常 A1 | connected=true, value=90, stop=false | 异常 | 超出练习范围；当前值 90 | 是 | 未执行；无日志 |
| 断开 D1 | connected=false, value=null, stop=false | 断开 | 输入断开；当前值清空 | 等待下一次输入 | 未执行；无日志 |
| 手动停止 S1 | connected=true, value=50, stop=true | 停止并锁定 | 已手动停止；当前值清空 | 否 | 未执行；无日志 |

核心用例执行统计：计划 4 项，实际执行 0 项，通过 0 项，失败 0 项，未执行 4 项。“通过 0”仅表示没有执行证据，不能据此计算通过率。

## 4. 容易漏掉的边界与先后顺序

下面 4 项是补充计划，也尚未执行：

| 用例 | 输入或顺序 | 预期结果 | 实际执行 / 证据 |
| --- | --- | --- | --- |
| 边界 B1 | 分别开启新运行，输入 20 和 80 | 两个值均为正常，因为边界包含等号 | 未执行；无日志 |
| 缺失 D2 | connected=true, value=null, stop=false | 断开；不沿用此前读数 | 未执行；无日志 |
| 优先级 S2 | connected=false, value=null, stop=true | 停止；停止规则优先于断开 | 未执行；无日志 |
| 恢复 R1 | 新运行：50 → 断开 → 90 → 手动停止 → 50；最后显式重开，再输入 50 | 正常 → 断开 → 异常 → 停止 → 仍停止；重开后正常 | 未执行；无日志 |

## 5. 怎样补成实际测试记录

1. 用自己的工具实现上述规则，写下工具版本、运行命令和输入回放方式。若实现采用不同规则，先改规则与预期列，不要运行后才迁就实际输出。
2. 每次记录输入时间、输入内容、前一状态、实际状态、当前值和采样是否继续。停止时还要证明后续输入没有重新激活采样。
3. 按用例逐项运行，将“未执行”替换为真实观察，并填写日志行号或截图文件名。实际值与预期不一致时标记失败并保留输入。
4. 补齐四类核心状态，再处理边界和恢复顺序；只有执行过的项目参与通过率计算。

建议交接包：本记录、输入序列表、实际程序/配置、启动说明，以及带用例编号的执行日志。没有硬件就继续如实标注“纯软件仿真”，不补写器件型号或接线照片。
