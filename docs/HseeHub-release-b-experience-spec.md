## 0. 决策摘要

Release A 已经完成最重要的结构性工作：HseeHub 不再是培养方案镜像，而是沿着「看懂专业 → 试一个项目 → 留下作品 → 再看下一步」组织内容。

Release B 不再重做信息架构，也不因视觉改版扩充通用 taxonomy 或治理字段。只有真实素材、可解释更新等现有模型确实无法表达的内容，才允许做最小、兼容、可验证的契约扩展。当前最需要解决的是：网站虽然有用、可信、功能完整，但仍像一份做成网页的说明书。下一阶段要把它变成一个学生愿意继续逛、愿意点开项目、过几天还想回来的探索桌面。

一句话目标：

> 让第一次来的学生在 5 秒内看懂这里能帮什么，在 5 分钟内找到一个愿意试的小项目，并能说清自己会留下什么。

本阶段作出六个决定：

1. **保留现有四项导航和内容事实源**，不再扩一级内容域。
2. **首页从“完整说明每一层”改为“动作优先的编辑流”**，同一项目只完整出现一次。
3. **去掉报告式编号、治理式眉题和卡面免责声明堆叠**；可信度保留，但按行动、理解、证据三层出现。
4. **用真实项目过程和持续维护痕迹增加在场感**，不伪造社区数据、学生引语、活动人数或完成记录。
5. **项目发现从五维筛选改为学生意图入口**；保留旧分享 URL 的兼容解析，内容达到 9–12 个项目后再恢复组合筛选。
6. **先用目标学生验证叙事和布局，再固化视觉基线**；不能用自动化截图代替理解测试。

## 1. 基线与证据边界

### 1.1 当前已经完成什么

当前版本已有：

- 首页任务启动台、3 个项目、双专业案例、作品到路径、FAQ；
- 「专业与课程 / 做个项目 / 能力地图 / 选下一步」四项导航；
- 2 个专业、8 类能力、3 个项目、6 个场景、5 条路径和来源体系；
- 项目步骤、停止条件、产物模板、资源入口和数据边界；
- Next.js 服务端核心内容、亮暗主题、响应式布局、键盘基础支持；
- 内容、链接、类型和构建门禁，以及 E2E/视觉测试脚本与部分正式基线。当前 `npm run check` 不包含 E2E/视觉，未跟踪 `test-results/` 也不能证明测试绿色；Release B 必须重新建立可复现的发布门禁。

当前工作区还有一个必须先收口的基线缺口：`/pathways/explore` 页面和复盘模板尚未进入版本控制，但已被首页 view model 与 sitemap 引用。Release B 决定保留“还没想好”的双路径短实验，因此 Phase 0 必须审阅并正式纳入这两个文件，同时补链接与 E2E 验证；完成前不得把该能力写成已发布功能。

因此，下一阶段的首要矛盾不是信息不够，而是：

```text
严谨信息已经足够
        ↓
学生仍需要快速看懂、产生兴趣、开始一次尝试
        ↓
要调整表达层、视觉层和验证方式，而不是继续扩数据模型
```

### 1.2 本轮参考站证据

2026-08-19 获取并复核了参考站公开首页 HTML、首页代码分块和 CSS 资源。可直接确认：

- 首页由 `home-main` 与 `home-side` 组成主列和侧栏；
- 游客快捷入口是「创建账号 / 知识 Wiki / 社区广场」，登录后切换为「实验室 / 写 Wiki / 社区消息」；
- 主列继续聚合上次任务、稍后再看、推荐活动、平台公告、最新动态、学习路线和近期活动；
- 侧栏根据状态展示个人足迹或注册价值，并放置日历、工具箱和全站数据；
- 视觉变量使用近黑正文、白/浅灰表面、蓝色强调、低对比分隔线、轻阴影和独立明暗主题；
- 首页内容通过 Wiki、社区、活动、Lab 等真实数据形成“这里正在发生事情”的感觉。

本轮浏览器截图链路受宿主可信路径限制，本文不声称完成 2026-08-19 的像素级视觉复刻；视觉判断同时参考仓库中 2026-08-13 与 2026-08-18 的既有直接审计。本文只迁移已被多份证据支持的设计逻辑，不复制品牌、组件像素或具体文案。

### 1.3 事实、推断与本项目决策

| 类型 | 示例 | 本文如何使用 |
|---|---|---|
| 事实观察 | 参考站打开即给快捷动作，并把公共内容和个人上下文并置 | 作为可迁移的组织逻辑 |
| 设计推断 | 社区感主要来自真实活动痕迹，而不是宣传口号 | 作为待验证的设计假设 |
| HseeHub 决策 | 用项目更新、作品过程和最近核验形成在场感 | 作为 Release B 的实施要求 |

## 2. 第一性原理

### 2.1 学生的不确定来自反馈太慢

对低年级学生来说，“选哪个专业、以后做什么”通常具备三个特征：选项抽象、后果遥远、自己没真正做过。

增加更多介绍只能提高信息量，不能缩短反馈回路。真正有用的机制是：

```text
一个真实困惑
  → 一个足够小、随时能停的任务
  → 一份看得见的结果
  → 对兴趣、能力和下一步的新判断
```

HseeHub 的第一职责是让这条回路开始运转，不是替学生给出结论。

### 2.2 首页的稀缺资源是注意力

首页每增加一段解释，就在推迟一次真实点击。首页必须优先回答：

1. 这和我有什么关系？
2. 我现在能做什么？
3. 做完会留下什么？

来源、许可、资格和边界仍然重要，但它们应在用户准备行动或核验时出现，不应在每张首页卡上重复占据主视觉。

### 2.3 亲切不等于随意，可信不等于公文

新的表达分三层：

| 层级 | 用户问题 | 语气与内容 |
|---|---|---|
| 行动层 | 我现在能做什么？ | 短句、具体动作、时间与产出 |
| 理解层 | 为什么这样做？哪里可能卡住？ | 过程、示例、停止条件和边界 |
| 证据层 | 依据是什么？什么时候核验的？ | 来源、版本、owner、复核日期 |

“去官方化”只改变前台表达顺序，不降低事实和安全标准。

### 2.4 在场感必须来自真实痕迹

HseeHub 暂时没有社区和高频用户数据，不能复制参考站的动态、热力图和排行榜。

本阶段允许使用的真实痕迹：

- 最近更新或最近核验的内容；
- 一份项目是怎样逐步做出来的；
- 真实或经授权的作品截图、设备、草图与批注；
- 有明确 owner、发布日期和过期规则的编辑精选；
- 清楚标注来源的合成演示产物。

本阶段禁止使用的伪痕迹：

- 虚构评论、点赞、参与人数或“同学都在看”；
- 未经访谈的学生引语；
- 游客态全为 0 的足迹、热力图和仪表盘；
- 没有真实内容供给的“最新动态”。

## 3. 现状诊断

### 3.1 应保留的优势

- 首页主线和四项导航已经正确，不需要再次推翻；
- 页面与内容事实源分离，适合换表达而不破坏证据层；
- 三个项目已经能形成“看条件 → 做步骤 → 留产物”的闭环；
- 本地 SVG、服务端输出和静态内容让性能基线较稳；
- 现有 token、暗色主题、reduced motion 与测试体系值得沿用。

### 3.2 为什么当前效果仍然一般

#### 页面像报告目录

首页高频使用 `B / C / D / E`，详情页高频使用 `01 / 02 / 03`，再叠加大标题、细线、眉题和小号元数据。它建立了严谨感，也让页面像验收文档。

编号只应服务真实顺序，例如项目步骤或一周实验；普通栏目不再编号。

#### 同一种卡片承担太多内容

专业、能力、项目、场景和路径大量复用“灰白底 + 细边框 + 轻阴影 + 元数据”的语法。信息类型不同，视觉记忆点却相同，长页面只剩下卡片网格的重复。

#### 首屏项目与下一节重复

首页首屏右侧完整展示第一个项目，紧接着下一节又遍历三个项目。移动端用户会先读一张信息密集的项目卡，很快再次遇到同一内容。

Release B 中首屏只展示项目预告，完整项目只在“今天先试一个”模块出现一次。

#### 治理文案过早出现

“许可、停止条件、共同验收、不是资格结论、编辑部整理、事实基线”等表述均有价值，但连续出现在首页主层，会让学生先感受到风险和制度，而不是任务和成果。

#### 项目发现方式像后台筛选

当前只有 3 个项目，却提供专业、能力、场景、视角、时长五组筛选。字段结构暴露给了用户，问题却没有被转译成学生会说的话。

#### 缺少人的痕迹和实体感

三个项目预览都是确定性生成的图表或矩阵，没有过程照片、设备台架、手写批注、材料样本或真实作品故事。网站可信，但不像校园里真正有人做过这些事。

### 3.3 必须顺手修复的体验债

- Skip link 应成为 `<body>` 内第一个可聚焦元素；
- 当前导航项应设置 `aria-current="page"`；
- 10–12px tertiary 文字的亮色对比度不足，普通正文必须达到 4.5:1；
- 移动项目元数据不能继续固定三列小字；
- 移动菜单需明确是非模态展开区，或实现完整模态焦点模型；
- 800 行以上全局 CSS 中存在多代页面语法，本阶段不得继续无边界追加 legacy 规则。

## 4. 从 SZTUBitByte 学什么

### 4.1 真正值得迁移的精髓

| 参考站逻辑 | 背后的价值 | HseeHub 的转译 |
|---|---|---|
| 打开就是快捷入口，不先做品牌宣讲 | 用户先完成任务，再理解产品 | 首屏直接给 3 个学生动作，并露出一个项目预告 |
| 多种内容进入统一信息流 | 不让用户理解后台内容模型 | 项目、问答、作品、更新使用统一编辑语法 |
| 公共内容与个人上下文并置 | 同时回答“有什么”和“我到哪了” | P1 用本地最近看过与本周尝试，不上账号 |
| 标题 + 类型 + 元数据 + 单一动作 | 在高密度中保持扫描效率 | 每张卡只保留最影响决定的 2–3 个字段 |
| 日历、动态、足迹都是真数据 | 产生持续发生感 | 用真实更新时间、作品过程和编辑精选代替假社区 |

统一编辑语法：

```text
类型标签 → 人话标题 → 一句结果导向摘要 → 2–3 个必要元数据 → 一个动作
```

不同内容仍保留类型特征：

- 项目：时长、最低基础、会留下什么；
- 专业问答：适用年级、问题结论、依据入口；
- 作品：做了什么、怎么做、哪里有限制；
- 更新：变了什么、更新时间、影响页面。

### 4.2 明确不照搬

- 不复制七项一级导航；
- 不建设账号、社区、评论、排行榜或热力图；
- 不复制 Ant Design 的后台视觉；
- 不复制品牌色、图标、卡片像素和动效；
- 不在没有真实数据时制造高密度仪表盘；
- 不把移动端顶栏塞满菜单、身份和主题按钮；
- 不为了统一卡片，抹掉每种内容真正影响决定的字段。

HseeHub 的频率和内容供给低于参考站，首页应比参考站更松、更聚焦、更像编辑策展，而不是更密。

## 5. Release B 产品目标与边界

### 5.1 用户优先级

主用户：

- 本院大一、大二学生；
- 转专业前后、对两个专业差异不确定的学生；
- 主要在手机上用 3–10 分钟找一次低成本尝试的人。

次用户：准新生、家长和希望整理项目证据的高年级学生。

教师和编辑是内容审阅者，不是首页叙事对象。

### 5.2 本阶段目标

1. 5 秒内说出网站用途；
2. 5 分钟内找到一个合适的小项目；
3. 说清项目耗时、最低基础和会留下什么；
4. 用自己的话说出两个专业的一个共同点和一个差异；
5. 知道需要时可以查看来源和边界，但不把本站误认为官方资格工具。

### 5.3 非目标

- 登录、评论、投稿、协作和社区；
- 个性化推荐算法；
- CMS 与治理后台；
- 站内执行代码、训练模型或处理真实患者数据；
- 岗位抓取、院校排行、薪资与录取预测；
- 用更多路径、能力或治理字段体现“完成度”。

## 6. 信息架构与全站壳层

### 6.1 一级导航保持四项

建议将标签进一步缩短，但不改路由：

| 当前 | Release B 标签 | 路由 | 用户问题 |
|---|---|---|---|
| 专业与课程 | 专业 | `/majors` | 两个专业到底在做什么？ |
| 做个项目 | 小项目 | `/projects` | 我今天能试什么？ |
| 能力地图 | 能力 | `/capabilities` | 课程和项目让我会什么？ |
| 选下一步 | 下一步 | `/pathways` | 做完后还可以往哪里走？ |

导航标签在 8 名目标学生测试中若出现理解歧义，可回退到当前文案；不为追求简短牺牲可理解性。

### 6.2 Header

桌面端：

- 品牌标记 + `HseeHub`；副标题只在宽屏显示；
- 四项导航；
- 主题切换使用图标和可访问名称，文本可隐藏；
- Header 高度控制在 60–64px，不制造学院门户式大横条。

移动端：

- 保留品牌和一个菜单按钮；
- 主题切换进入菜单底部，减少顶栏拥挤；
- 菜单打开后可 Escape 关闭，关闭后焦点返回按钮；
- 当前项使用 `aria-current="page"`。

## 7. 新首页规格

### 7.1 页面主线

```text
Header

① 先别急着选，动手试一次
   站点一句话 + 3 个动作入口 + 1 个项目短预告

② 今天先试一个
   1 个重点项目 + 2 个紧凑项目条目

③ 同一道题，两种工程视角
   双专业协作案例，不做专业优劣对照

④ 做完以后，你会留下什么
   作品过程 / 结果预览 + 2–3 条下一步用法

⑤ 最近整理了这些
   真实更新时间、FAQ 与可信入口

Footer
```

普通栏目不再使用 A/B/C 或 01/02/03 编号。

### 7.2 首屏

推荐首屏文案：

```text
给健康工程学生的探索桌面

先别急着选。动手试一次。

看懂两个专业在做什么，挑一个小项目，
留下一份别人能看懂你做过什么的作品。

[两个专业到底差在哪]
[给我一个能马上试的项目]
[我还没想好，从这里开始]
```

项目短预告只展示：

- 一张有记忆点的局部视觉；
- 项目标题；
- `10 分钟预览 · 约 90 分钟实践`；
- 产出一句话；
- 单一动作「看看今天怎么开始」。

禁止在首屏短预告中展示完整项目卡、三列元数据、全部资源状态、数据许可和免责声明。

### 7.3 首屏布局

以下“首屏可见”均指默认文字缩放和指定 viewport；200% zoom 时允许内容自然下移，不得为了维持一屏而缩小或截断文字。

桌面 1440px：

- 12 栏网格，主文案 7 栏、项目预告 5 栏；
- 视觉不追求对称，项目预告可轻微越出文字基线，形成编辑感；
- 900px 高视口内必须看到站点用途、三个动作和项目标题；
- 不使用大面积空白模拟“高级感”。

移动 390px：

- 单列；
- 先出现主张、简短说明、三个入口；
- 项目预告仅保留缩略视觉、标题、耗时和动作；
- 844px 高视口内看到至少一个可执行项目标题；
- 项目完整详情下沉到下一模块或详情页。

### 7.4 「今天先试一个」

三个项目只完整出现一次，布局为：

- 一个重点项目：较大视觉、适合谁、会留下什么、时长、基础、一个动作；
- 两个紧凑条目：标题、项目世界的视觉标记、时长、产物、一个动作；
- 桌面形成 7+5 的非对称组合，移动按重点项目 → 两个条目排序。

项目入口不再先问五组筛选字段，改为四个学生式意图。它们只负责排序和解释，不隐藏其他项目，也不把 10 分钟导览冒充 90 分钟项目完成：

| `?intent=` | 用户文案 | 首个结果 | 点击后的诚实反馈 |
|---|---|---|---|
| `quick-look` | 我先看 10 分钟 | 合成信号分类 | 这是 10 分钟导览；完整实践约 90 分钟 |
| `data-ai` | 我想碰数据 / AI | 合成信号分类 | 先看数据、特征和结果解释会做什么 |
| `sensor` | 我想动手接传感器 | 传感—采样—告警 | 优先使用仿真或低压台架，完整实践约 2 小时 |
| `portfolio` | 我想做一份能展示的作品 | 三个项目保持可见，按产物完整度说明 | 三个项目都会留产物，先比较时间和媒介 |

新 UI 使用稳定的 `?intent=` 分享契约。当前 `major/capability/scenario/viewpoint/duration` 查询参数至少保留一个发布周期的兼容解析：旧链接继续按原条件展示，并出现可关闭的“正在使用旧筛选链接”提示；未知值不静默清空页面。兼容期结束前，需先检查已有链接和访问记录，再决定重定向或退役。

意图到项目的展示映射由 view model 维护，不为三个项目增加泛化 taxonomy。项目达到至少 9–12 个后，再评估组合筛选。

### 7.5 「同一道题，两种工程视角」

保留双专业协作，但从对照表改为一次问题拆解：

```text
真实问题
  ↓
智能医学工程会先看什么 / 做出什么
  ↔ 交接物与共同验收
生物医学工程会先看什么 / 做出什么
```

要求：

- 标题先说学生问题，不先说专业定义；
- 每侧最多 3 个动作；
- 视觉上使用共享问题作为中心，不用红蓝阵营式对抗；
- 一屏内看见共同目标和交接关系；
- 详细课程和来源继续下沉。

### 7.6 「做完以后，你会留下什么」

当前“产物到三条路径”逻辑保留，但先展示作品本身：

- 一张项目过程或结果视觉；
- 问题、输入、做法、结果、限制五个简短批注；
- 旁边显示 2–3 种真实改写方式；
- “可复核产物”在前台翻译为“别人能看懂你做过什么的记录”；
- 路径结论不能写成录用、录取或资格承诺。

### 7.7 「最近整理了这些」

本模块用真实、可追溯的维护记录制造在场感。不得仅按共享的 `updatedAt`、`lastVerified` 或内容基线日期生成“更新”：批量迁移和重新核验不等于内容发生变化。

Release B 新增最小 `content/updates.json` 契约：

```text
id / entityType / entityId
kind: content-update | source-reverification
summary / publishedAt / owner
```

要求：

- 记录必须关联存在的实体，并通过内容校验；
- `content-update` 必须说明对学生可见的变化；
- `source-reverification` 使用“已重新核验来源”文案，不伪装成新增内容；
- 按 `publishedAt` 倒序，同日按 `id` 稳定排序，展示绝对日期；
- 最多 3 条；没有摘要、owner 或可追溯变更时隐藏整个模块；
- 右侧或模块底部提供「依据与更新时间」入口。

FAQ 首页只保留 3 个最影响下一步的问题，不再附“非学生原话”“事实基线”等治理说明；在 FAQ 页或 About 中说明编辑原则。实现时同步把 `getHomePageModel()` 的 4 条硬阈值改为 3 条，并增加少于 3 条时失败的内容回归测试。

## 8. 视觉与内容语言

### 8.1 视觉气质

关键词：

```text
学生实验桌 / 编辑策展 / 温暖克制 / 有实体感 / 可以开始
```

避免：

```text
学院门户 / SaaS 后台 / 验收报告 / 大面积品牌宣言 / 全站卡片墙
```

### 8.2 建议色彩角色

以下为高保真起点，不是无需验证的最终色值：

| Token | 建议值 | 用途 |
|---|---:|---|
| `--color-canvas` | `#F6F4EF` | 温暖页面底色 |
| `--color-surface` | `#FFFDF8` | 主内容表面 |
| `--color-ink` | `#171A1F` | 主文字 |
| `--color-muted` | `#59616E` | 普通次级文字，需满足 AA |
| `--color-brand` | `#355C7D` | 导航、链接、主动作 |
| `--color-accent` | `#B94F35` | 可用于 AA 正文的小面积暖色强调 |
| `--color-success` | `#2E7D61` | 资源可用与完成状态 |
| `--color-line` | `#D8D6CF` | 低对比分隔线 |
| `--color-control-border` | `#73777F` | 表单与交互控件边界 |
| `--color-focus` | `#2458D3` | 键盘焦点环 |

暗色主题不直接反相，起点如下：

| Token | 暗色建议值 |
|---|---:|
| `--color-canvas` | `#121418` |
| `--color-surface` | `#1A1E24` |
| `--color-ink` | `#F0F2F5` |
| `--color-muted` | `#B7BEC8` |
| `--color-brand` | `#8CB4D9` |
| `--color-accent` | `#F09679` |
| `--color-success` | `#75C4A4` |
| `--color-line` | `#323841` |
| `--color-control-border` | `#8F98A5` |
| `--color-focus` | `#9AC2FF` |

规则：

- 蓝色不再覆盖所有信息类型；
- 强调色只占页面小面积，不给整张卡染色；
- 状态不能只靠颜色；
- `--color-line` 只用于装饰分隔，不能作为控件唯一边界；
- 10–12px 小字不得使用当前低对比 tertiary 色；
- 所有正文和交互状态满足 WCAG 2.2 AA。

### 8.3 字体与字级

- 明确选择一种可复现的字体策略：自托管已授权字体，或只使用稳定系统字体；
- 不继续声明未加载的 Web Font 作为首选；
- 中文主标题不小于 32px（移动）/ 48px（桌面）；在默认字号和指定 viewport 下以两行内为设计目标，但不得截断或 clamp，文字放大后允许自然增加行数；
- 正文移动端不小于 15px，关键元数据不小于 12px；
- 等宽字体只用于时间、版本、数据或真实代码，不用于栏目编号装饰；
- 字重层级不超过 4 档，避免每张卡都同时出现 800/700/600/500。

### 8.4 形状、边框和阴影

- 内容卡圆角建议 12–16px，按钮 8–10px，标签可用胶囊形；
- 同一屏最多两种圆角角色；
- 阴影只用于可交互或悬浮层，静态内容优先靠间距和表面区分；
- 不给每个 section 加全宽上边线；
- 列表、作品批注、对照关系要有各自语法，不能全部变成卡片。

### 8.5 项目视觉资产

三个项目必须形成三个不同的“项目世界”：

| 项目 | 视觉方向 | 不再只使用 |
|---|---|---|
| 合成信号分类 | Notebook 片段、曲线批注、特征选择过程 | 一张完成态折线图 |
| 传感采样 | 台架、接线、阈值测试、记录表 | 一张抽象统计图 |
| 材料选择 | 材料样本、约束便签、权衡矩阵过程 | 一张完成态矩阵 |

Release B 最小发布门槛：

- 代表项目「合成信号分类」提供首页/列表、过程、结果/产物 3 张完整视觉；
- 另外两个项目各提供至少 1 张可辨认的首页/列表视觉，并保留现有结果预览；
- P1 再把另外两个项目补齐到每个 3 张。

素材契约采用兼容迁移，不把多个资源塞进单个 `preview`：将 `Project.preview` 演进为 `previewAssets: ProjectPreview[]`，沿用现有 `src/alt/kind/author/license/sourceRef/generationRef` 元数据。迁移期读取层把旧 `preview` 适配为单元素数组；三个项目与所有消费者迁完、校验和构建全绿后再删除旧字段，禁止长期双写。

资产性能预算：

- 单张栅格图在最大实际渲染尺寸下压缩后不超过 200KB；
- 首屏图片总传输预算：移动 ≤ 350KB、桌面 ≤ 500KB；
- 栅格优先 AVIF/WebP，图表与线稿可保留 SVG；
- 每张图提供固定 `width/height` 或 `aspect-ratio` 和响应式 `sizes`；
- 只有首屏主视觉可 priority，其余默认 lazy-load；
- 禁止无必要 autoplay 视频、背景视频和仅为装饰加载的大图。

素材优先级：

1. 经授权的真实项目过程与作品；
2. 基于本站实际项目步骤制作的原创插画或重建画面；
3. 明确标注的确定性合成预览。

第 2、3 类只能证明项目流程被认真表达，不能作为“真实学生已经参与”的在场感证据。

不使用与项目无关的校园图库、泛医疗 AI 图或虚构学生照片。每份素材必须登记 `alt`、作者、许可、来源和更新时间。

### 8.6 文案转换规则

| 当前倾向 | Release B 表达 |
|---|---|
| 可复核产物 | 一份别人能看懂你做过什么的记录 |
| 完整步骤、许可和停止条件在详情里 | 先看时长和会做出什么，合适再开始 |
| 它不是录取、录用或资格结论 | 想确认资格？去官方入口看最新要求 |
| 事实基线 | 依据与更新时间 |
| 输入、输出和共同验收怎样交接 | 两边各做什么，最后怎么接起来 |
| 资源状态由 endpoint 聚合 | 现在能不能开始 |

写作规则：

- 标题优先使用问题、动作或结果；
- 一句话尽量只承载一个判断；
- 首页每屏最多一处边界提醒；
- 不连续使用“不是、不代表、不替代”；
- 不用“赋能、助力、全面了解、人才培养、就业前景”等官网套语；
- 没有访谈依据时不加引号伪装学生原话。

## 12. 验证与指标

### 12.1 发布前主指标：可用性任务成功率

定义：目标学生进入首页后，能够选择一个项目，并继续查看开始条件或产物模板的比例。分母为参与该任务的有效测试人数，分子为无主持人提示完成上述序列的人数。

未接入隐私合规埋点前，只报告可用性任务成功率，不使用线上转化率名称，也不假装已有行为数据。

若后续接入匿名事件，才启用线上 `Meaningful Start Rate`：分母为看见首页任务/项目入口的去重匿名会话，分子为同一会话内完成以下合格序列的会话。

```text
home_task_or_project_click
→ project_detail_view
→ start_conditions_view
→ resource_open 或 artifact_template_open
```

启用跨会话标识前必须明确隐私说明、保留期、Do Not Track/Cookie 策略；模板打开不能冒充项目完成。

### 12.2 两轮学生验证

每轮样本：8 名目标学生，至少 6 名大一/大二，至少 4 名主要使用手机。第二轮至少 4 名为未参加第一轮的新样本，以降低学习效应。

改版线框测试前，先让 Release A 用同一任务和评分规则完成一次基准测试；没有基准时只能判断新版是否达线，不能宣称相对改善。

第一轮在线框/真实文案阶段完成，不等高保真：

1. 5 秒看首页后，说出网站是做什么的；
2. 找到一个“自己现在能试”的项目；
3. 说出该项目需要多久、会留下什么；
4. 解释两个专业的一个共同点和一个差异；
5. 找到依据或官方确认入口。

5 秒测试应在页面隐藏后要求开放式复述；“是否误认官方资格工具”使用非诱导问题和预先定义的评分规则，不直接问“你会不会误认”。

第二轮在 Release Candidate 完成，验证相同任务与移动端操作。

P0 通过线：

- 至少 6/8 能在 5 秒测试中说出“看专业 / 做项目 / 找下一步”中的两项；
- 至少 6/8 在 5 分钟内找到合适项目；
- 至少 6/8 能说清项目产物；
- 至少 6/8 能说清一个共同点和一个差异；
- 至少 7/8 不会把本站误认为官方资格判断工具；
- 至少 6/8 认为页面更像“学生工具/探索站”，而不是“学院通知/培养方案网页”。

### 12.3 自动化与人工门禁

新增 `@axe-core/playwright` 或等价集成和 `test:a11y`，并建立 `check:release-b` 聚合门禁：`npm run check`、关键 E2E、a11y 和视觉回归全部绿色。快照更新本身不算通过，必须人工确认差异符合 Spec。

视觉矩阵使用默认文字缩放：

| 路由/状态 | 1440×900 light/dark | 390×844 light/dark | 320×800 light |
|---|---:|---:|---:|
| `/` | viewport + light full page | viewport + light full page | reflow |

交互与内容矩阵：

- `/`、`/projects`、代表项目页完成禁用 JavaScript 内容与链接检查；
- Header、首页任务入口、项目意图入口、代表项目开始动作完成纯键盘路径；
- 320px 检查上述三个核心路由无横向滚动；
- 在真实浏览器执行 200% zoom，不能用缩窄 viewport 代替；允许标题增加行数，不得丢内容或遮挡焦点；
- “来源两次点击内可达”的起点是任一已渲染高风险陈述，终点是原始官方/来源 URL；一次打开本站证据层、第二次进入原文；
- RB-08 由文案清单审核：无装饰章节编号、无首页卡面治理堆叠、每模块单一问题、每卡单一主动作、术语使用第 8.6 节转换规则。

无障碍覆盖：

- 普通文字对比度 ≥ 4.5:1，非文本交互边界和焦点状态 ≥ 3:1；
- skip link 为首个可聚焦元素；焦点可见且不被 sticky Header 遮挡；
- 交互元素具备正确 name/role/value，当前导航有 `aria-current`；
- heading 层级、main/nav/complementary/region landmark 合理；
- 内容图片有有意义的 alt，纯装饰图明确忽略；
- 异步筛选和资源状态变化提供可感知的状态消息；
- 交互目标至少满足 WCAG 2.2 的 24×24 CSS px，主要移动按钮目标为 40px 以上；
- `prefers-reduced-motion` 下无非必要移动；
- axe 自动检查全绿后，仍完成键盘、屏幕阅读器快速检查和真实 200% zoom。

性能与真实设备：

- 至少在 Android Chrome 与 iOS Safari 各完成一次首页、菜单、项目开始动作的真实设备检查；
- 自动化不能替代 5 秒理解测试、文案复述和真实设备检查。

## 13. 实施顺序与切线

### Phase 0：冻结基线与内容减法（0.5–1 天）

- 记录当前工作区和正式视觉基线；
- 将旧 next-stage 文档标记为 Release A 历史记录；
- 审阅并正式纳入当前未跟踪的 `/pathways/explore` 和复盘模板，补链接与 E2E；
- 完成首页内容“保留 / 改写 / 下沉 / 删除”清单；
- 统一 Header 标签、首页一句话与项目卡字段预算。

完成条件：团队能说明 Release B 不重做 IA、不扩内容域。

### Phase 1：真实文案线框与第一次验证（2–3 天）

- 先让 Release A 完成同题基准测试；
- 用现有真实内容完成 1440×900 与 390×844 线框；
- 先验证首页、项目发现、双专业协作和作品模块；
- 完成第一轮 8 人测试；
- 只在证据指向明确时调整结构。

完成条件：首轮核心任务至少 6/8 通过。

### Phase 2：视觉原语与素材（3–5 天）

- 实现新 token、字体策略、section、feature、compact row、artifact annotation；
- 为代表项目补齐首页/过程/结果三类视觉，另外两个项目各补一张独特入口视觉并保留现有结果预览；
- 修复 P0 可访问性债；
- 不进行无关的全站代码重构。

完成条件：三个项目视觉可辨认，核心组件通过亮暗与移动检查。

### Phase 3：首页与项目闭环（3–4 天）

- 实现首页 ①–⑤；
- 重做 `/projects` 的意图入口；
- 完成一个代表项目详情，再推广到另外两个；
- 保持来源和安全边界可达。

完成条件：RB-01 至 RB-07 通过。

### Phase 4：专业对照与全站收口（2–3 天）

- 改造 `/majors` 与 `/majors/compare`；
- 让能力和路径首层页面继承新壳层、token 与可访问性修复，不在 P0 重排其内容；
- 统一 About、Footer、metadata 与 README 表达，并核对 sitemap 路由完整性；
- 稳定后清理确认未使用的 legacy 样式。

完成条件：RB-08 与 RB-09 通过。

### Phase 5：Release Candidate 验证（2–3 天）

- 完成第二轮 8 人测试；
- 更新视觉基线；
- 运行完整工程、性能、可访问性与真实设备检查；
- 记录所有例外的风险、owner 和到期日。

完成条件：第 12 节全部 P0 门禁通过。

总估算：15–24 人日，其中产品/内容/设计约 6–9 人日，工程约 7–11 人日，招募、访谈与验证约 2–4 人日；真实作品授权和学生招募会额外影响日历时间。若素材未获授权，先使用基于本站项目过程制作的原创画面，不以图库或假学生故事填补。

### Release B 最小切线

最小可发布范围全部是阻断项：

1. 首页去重复、去报告化和移动首屏；
2. 项目发现与代表项目详情；
3. 代表项目三张视觉、另外两个项目各一张独特入口视觉及资产性能预算；
4. 可访问性、Release A 基准与两轮验证；
5. 专业对照；

可后置到 P1：

1. 能力与路径的内容重排；
2. 另外两个项目补齐三张视觉；
3. 本地最近看过与本周想试。

不得为了保留 P1 最近看过，牺牲 P0 学生验证或可访问性修复。

## 15. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 去官方化变成不严谨 | 来源和边界被删掉 | 使用三层表达，证据层始终两次点击内可达 |
| 模仿变成换皮 | 复制参考站蓝色、侧栏和卡片 | 只迁移动作优先、真实痕迹和统一编辑语法 |
| 没有真实素材 | 页面继续只有图表，或转而用无关图库 | 使用实际项目过程的原创重建画面，并明确来源 |
| 视觉先行掩盖任务问题 | 高保真完成后才发现学生不懂 | 在线框和真实文案阶段完成第一次测试 |
| 首页再次膨胀 | 更新、FAQ、作品、路径都要完整展示 | 每模块单一问题、固定内容预算、无真实内容即隐藏 |
| CSS 继续堆叠 | 新旧语法并存，维护更难 | 先分区，后清理；体验提交与机械重构分开 |
| 本地状态被误当账户 | 用户以为能跨设备保存 | P1 明示仅保存在本机，并提供清除入口 |
| 视觉基线锁死错误设计 | 为了快照不敢改布局 | 学生验证优先于旧快照，RC 时再建立新基线 |

## 16. 最终判断

Release A 解决了“网站应该讲什么”；Release B 要解决“学生为什么愿意继续用”。

HseeHub 不需要看起来像更现代的学院官网，也不需要假装已经拥有一个活跃社区。它应该像一张有人认真整理过、能马上开始的学生实验桌：

```text
我先看见一件能做的事
→ 我知道大概要花多久、会留下什么
→ 我愿意点进去试一次
→ 做完以后，我对专业和下一步有了新的证据
```

下一阶段的完成标准不是新增多少页面、字段或卡片，而是学生是否更快开始，页面是否更像真实的校园工具，以及严谨信息是否在需要时仍然可靠可达。
