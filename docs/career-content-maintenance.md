# 就业实习内容维护

当前方向：医工、软件与 AI 并重。求职页覆盖认识岗位、积累证据、找到机会、准备申请和复盘调整；后续按需继续更新。这里记录内容维护方式，不改变现有发布验收状态。

## 更新一次内容

1. 从完整的企业官方岗位说明或平台官方页面读取变化。记录精确 URL、查看日期和本次真正读到的任务或要求；页面标题或 HTTP 200 不能证明岗位在招。
2. 在 `roles[].sources` 更新岗位样例摘要。学历、专业、工具和时间要求只归属于该样例，不写成整个方向的统一门槛。没有公开截止日期时不推断期限。
3. 将编辑建议写在 `readiness`、`interviewQuestions` 和 `projectEvidence`，与来源摘要分开。项目只使用已有记录可以支持的证据，课程、仿真和合成数据练习保持原有身份。
4. 能力、项目、资源通过 ID 引用；在指南更新后，详情页关联卡从同一数据源生成。不要在页面中再维护一份岗位名称或项目链接。
5. 只更新本次实际检查过的内容日期。指南与资源目录各有自己的复核日期，更新其中一份不代表原有培养事实或整条路径已重新审核。
6. 运行 `npm run career:check`、`npm run practice:check` 和 `npm run check`；涉及页面交互时运行 `npm run test:e2e`，并检查就业页、受影响能力/项目页的手机布局及明暗主题。视觉变化需审阅并更新相应基线。

## 练习与示例

短练习提供输入、三步操作、产物与自查，时间只作为练习预算。编辑练习有独立日期，不刷新原课程事实或项目核验日期。场景页按已有能力关系选择练习；岗位页从对应能力进入，保留项目原来的资源与 Starter 状态。

完整填写示例使用明确标注的手工合成输入或状态设计。算数结果需能从所列输入复算；测试计划的实际执行栏保持“未执行”，直到确有运行证据。网页上的证据与简历句式要与下载内容一致，不能把计划写成已经完成的训练、测试或系统部署。模板许可与实际输入数据的许可分别填写。

## 过期与失效

已到复核日期的指南仍然可读，并显示复核提示；不隐藏已有项目关联，也不刷新旧日期伪装为最新。失效的岗位样例可以用新的官方样例替换，保留与当前任务相关的建议并重新核对。目录入口更换时检查实际域名、页面用途和申请入口，不能用一次机器请求代替岗位内容核验。
