# WP0 改前基线证据

## WP-1 基线对齐决策

在确认前，三种方案的风险与推荐如下：

| 方案 | 风险 | 结论 |
| --- | --- | --- |
| merge `origin/main` 到当前 `main` | 保留当前分支历史但会生成额外合并提交；若工作区后来有改动，冲突范围更难隔离 | 不推荐 |
| rebase 当前 `main` 到 `origin/main` | 重写本地提交 ID；后续审计和回滚需要额外解释，不能覆盖用户改动 | 不推荐 |
| 从 `origin/main` 创建 `codex/phase-1.6` | 基线清晰、可与 `main` 并行，保留未跟踪用户文件，后续可独立审查和回滚 | 推荐，已由用户确认并执行 |

执行结果：当前分支为 `codex/phase-1.6`，HEAD=`e6df957612d45d9cfbefe85d2690f8a1d1419e50`，直接从 `origin/main@e6df957` 创建；没有执行 merge、rebase、reset 或覆盖式 checkout。

## 观察记录

### 首页

- 390×844 的 H1 位于 y=133–206，三个任务入口完整可见，但第二个主区段标题从 y=746 开始，后续专业/能力/项目内容需要继续滚动；页面约 7.4 个移动视口高。
- 768×1024 的三个任务入口位于 y=241–494，能力精选在中等宽度开始形成双列，页面仍有 4.5 个视口高。
- 1440×900 的三个任务入口同一行位于 y=331–413，比较区段标题从 y=573 开始；页面整体约 3.4 个视口高。
- 现有首页继续全量展示 8 项能力、3 个项目、6 个场景和 FAQ；信息区段之间大量使用相同的边框、圆角、表面和交替背景，内容类型辨识依赖阅读标题。

### `/majors`

- 390×844 的两个专业卡纵向展开，首个“看懂这个专业”链接在 y=871 才出现；完整对照和课程叙事明显后置。

- `/majors` 与 `/majors/compare` 同时承担专业比较叙事，入口语义重叠，后续需要冻结 canonical。

### `/capabilities`
