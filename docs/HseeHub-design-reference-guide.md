# HseeHub 网站设计参考与课程排版指南

本轮范围：参考 SZTUBitByte 的公开界面，调整 HseeHub 首页和专业页的学习入口、内容层级与排版。保留现有路由、内容事实源与 Starter 状态判断。未发布到线上。

## 参考站观察

2026-09-30 实际浏览 [首页](https://sztubitbyte.com/)与[学习路线](https://sztubitbyte.com/paths)，观察为未登录状态。首页采用紧凑顶栏、快捷入口、内容分区和工具箱；学习路线采用目录、分组章节、阶段条目、定位入口和进度区。仅研究可见界面，未验证登录后的进度同步或后台实现。

| 可见设计 | 解决的问题 | HseeHub 的应用 |
| --- | --- | --- |
| 快捷入口先于大段介绍 | 首次访问快速找到动作 | 保留三个探索入口、主次动作与真实可用状态 |
| 路线 → 分组 → 条目 | 把大主题拆成可理解的学习单元 | 专业 → 学习阶段 → 课程与能力 → 选修方向 |
| 内容分区和定位入口 | 降低长页面的查找成本 | 首页显示课程摘要，专业页展开目录，`#learning-map` 直达 |
| 卡片、细分隔线、统一间距 | 用视觉层级表达关系 | 两列专业路线、编号阶段、浅色专业头部、独立行动栏 |
| 阶段进度与当前任务 | 支持返回后继续学习 | 当前采用真实作品与下一步链接；没有学习记录时不显示虚构进度 |

以上是基于页面观察的设计分析，并非参考站作者对设计意图的说明。HseeHub 使用现有蓝色与青色语义 token，兼容亮暗主题；借鉴信息组织，不复制品牌、素材或账号体系。

## 培养内容怎样转成网页

以 `content/site-data.json` 的 `majors` 为内容来源：`learningStory` 表达学习阶段，`courseEvidence` 表达课程能支持的任务，`electives` 表达进一步探索方向，`cohort` 和 `sourceId` 绑定年级与来源。

本轮核对了学院的[智能医学工程介绍](https://hsee.sztu.edu.cn/info/1107/2351.htm)与[生物医学工程介绍](https://hsee.sztu.edu.cn/info/1107/2352.htm)。公开介绍支持两专业的交叉基础与课程侧重；它们不等于完整的 2025 级正式培养方案。本轮没有取得正式方案原件，未重新确认学分或逐学期排课，也未修改已有事实核验日期。

课程层级以“学什么、能做什么、到哪里查看依据”组织：智能医工突出数据与智能系统，生医工突出测量、材料、检测与仪器，同时保留共同工程基础。学习阶段是编辑导览，不标作官方学期，也不推导难度、专业排名或就业资格。

首页保持“先行动 → 看专业差异与课程入口 → 尝试项目 → 查看产物与方向 → 来源”主线。专业页将完整学习目录放在专业概览后，课程能力默认展开，选修方向按需展开；课程版本与依据链接放在各自专业卡底部。

## 后续页面排版准则

1. 一块内容只回答一个学生问题；标题表达任务，正文补充课程与约束。
2. 首页用摘要与入口，详情页用分组目录；不要把培养方案全文堆到首页。
3. 桌面并列比较专业，手机单列阅读。使用原生 `details` 渐进展开，禁用 JavaScript 时仍可阅读。
4. 课程事实从内容层读取，专业名称、年级、课程与来源不复制到组件常量。
5. 只有取得逐学期正式方案后才增加学期表；学习进度必须来自真实记录。
6. 修改后检查窄屏溢出、键盘操作、亮暗主题、来源链接和已有行动链；布局变化需要重新审阅视觉基线。
