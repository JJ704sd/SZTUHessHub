## 0. 一页结论

HseeHub 下一阶段不应继续扩充更多路径、字段或说明页，而应把现有内容重新组织成一个学生愿意使用的「探索桌面」。

新的核心主线是：

```text
看懂专业 → 试一个小项目 → 留下可复核作品 → 再看下一步方向
```

一句话产品定义：

> HseeHub 是给健康工程学生用的探索桌面：先看任务，动手试一次，再决定往哪里走。

下一阶段最重要的五个决策：

1. 首页服务第一次来的学生，不服务内容审核人员，也不直接充当五类发展路径总览。
2. 首页首屏从大段说明改为任务启动台，3 分钟内能找到一个入口，10 分钟内能选定一次低风险尝试。
3. 现有五类路径、行动阶梯和证据模型保留为深层可信底座，但完整内容下沉到 `/pathways` 与详情页。
4. 可信度采用分层表达：卡面说人话，详情讲边界，信任中心保留来源、版本和核验状态。
5. 视觉气质从「学院报告/合规门户」调整为「克制、温暖、可操作的校园工具」。

这不是一次换色或重新做 Hero，而是一次信息优先级重排。

## 1. 为什么现在必须重构

### 1.1 当前项目已经出现两套主叙事

仓库已提交的 v1 内容主线是：

```text
双专业 → 能力与课程 → 项目 → 应用场景
```

当前未提交工作区又新增了：

```text
就业 / 国内深造 / 公共服务 / 海外深造 / 独立发展
→ 已有资产 → 新增门槛 → 四档行动 → 证据转换
```

新增内容本身有价值，但它已经替换首页主叙事：`app/page.tsx` 当前只渲染开始方式、五类路径、证据转换和行动阶梯。与此同时，品牌、README、About、页尾和大量旧页面仍在讲「健康工程双专业探索」。

直接后果是：第一次来的学生还没理解本站、学院和两个专业，就被要求思考就业、考研、考公、留学或独立发展。

### 1.2 当前问题不是信息不足，而是出场顺序错误

现有库存已经很充足：

- 2 个专业；
- 2 个同题双解案例；
- 8 类可迁移能力；
- 3 个可执行项目；
- 6 类应用场景；
- 5 条发展路径；
- 3 类项目产物与 5 种证据转换；
- 来源、事实状态、资格边界和最后核验时间。

问题在于同一层级出现了太多内容。当前首页在桌面端将五条路径的「平时做什么、可能已有、通常还要补、先试一步」全部平铺，手机端则成为很长的连续说明流。

### 1.3 当前可信，但不亲近

现有页面有完整的亮暗主题、语义 token、响应式布局和内容关系校验，这些都应保留。但页面高频使用大标题、编号眉题、表格、细线、事实状态、来源等级和资格边界，且几乎没有真实作品、设备、校园空间或学生场景素材。

结果是「很严谨」，但更像项目报告、教务说明或合规门户，不像学生会反复打开的工具。

## 2. 第一性原理

### 2.1 学生真正缺少的不是更多选项

学生的不确定通常来自：

```text
选项很多 + 后果遥远 + 自己没有做过 + 缺少低成本反馈
```

因此，继续增加说明、路径和免责声明不能直接降低不确定。真正有效的产品机制是：

```text
模糊问题
  ↓
一个足够小、可以停止的任务
  ↓
亲手完成后的感受与产物
  ↓
对专业、能力和方向的新判断
```

### 2.2 本站不替学生选择，而是缩短反馈回路

HseeHub 不应回答「哪个专业更好」「我一定适合什么」「这条路径能不能上岸」。

它应帮助学生更快回答：

- 我愿不愿意继续做这种任务？
- 我已经具备哪些基础？
- 我能不能先做出一个小结果？
- 做完后，我还想往哪边继续？

### 2.3 可信度不等于公文语气

可信度需要三层，而不是把所有治理信息放到卡面：

| 层级 | 用户问题 | 表达方式 |
|---|---|---|
| 行动层 | 我现在能做什么？ | 人话、短句、明确动作 |
| 理解层 | 为什么这样做，有什么边界？ | 解释、注意事项、停止条件 |
| 证据层 | 这条信息从哪来，何时核验？ | 来源、版本、claim、状态、复核日期 |

底层证据模型继续严格，表层语言可以自然。

## 3. 目标用户、任务与产品边界

### 3.1 目标用户

P0 主用户：

- 本院大一、大二学生；
- 转专业前后、对两个专业差异不确定的学生；
- 主要在手机上用 3–10 分钟找方向或找一次尝试。

P1 次用户：

- 准新生与家长：快速看懂共同底座和不同任务；
- 大三、大四学生：把课程和项目转换为求职、深造等方向可用的证据。

非首页主用户：

- 教师、行政与内容审核人员；
- 需要个体资格判断的人；
- 招聘、招生或商业撮合平台用户。

教师可以是内容审阅者，但不是首页叙事对象。

### 3.2 核心 Jobs to Be Done

1. 「两个专业到底每天在做什么？」
2. 「我现在会的东西能做出什么？」
3. 「这周先试哪个，不合适能不能停？」
4. 「做完以后，这份东西还能带我去哪里？」

### 3.3 目标反馈回路与待验证假设

```text
3 分钟找到入口
10 分钟选定一次低风险尝试并拿到开始条件与产物模板
```

「7 天内留下一个可复核产物」是待验证的用户行为假设，不是本站可以单方面兑现的产品承诺。P0 通过 7 天后访谈或可选完成标记了解结果；本站不要求用户上传作品，也不把产物完成率当作首发上线门槛。

### 3.4 本站是什么 / 不是什么

本站是：

- 健康工程学生的探索桌面；
- 专业、能力、项目和方向之间的连接器；
- 低成本验证兴趣与任务偏好的起点；
- 有来源、有边界的编辑策展站。

本站不是：

- 学院官网或培养方案镜像；
- 专业、岗位、院校、薪资或录取概率排行榜；
- 个体资格判定或职业承诺工具；
- 当前阶段的大而全社区；
- 真实患者数据处理或站内任意代码执行环境。

## 4. 从参考站学习什么

2026-08-18 对 SZTUBitByte 首页前端实现、公开静态资源与公开页面呈现的复核显示，其真正值得学习的不是品牌色或具体卡片样式，而是以下设计逻辑。

### 4.1 值得迁移的精髓

#### 打开就能做事

参考站没有用大幅品牌宣言占据首页，而是把账号、Wiki、社区、近期活动、工具箱等真实入口前置。首页首先回答「现在能做什么」。

HseeHub 的对应做法：首屏直接给看专业、试项目、未定方向三个任务入口，并至少露出一个具体项目。

#### 不同内容进入统一信息流

参考站让 Wiki 与社区共用统一动态流，同时让活动保留日期、地点等必要类型特征。共同之处是清晰标题、轻量元数据和单一动作，而不是把所有内容强行做成同一种卡片。用户不需要先理解后台内容模型。

HseeHub 的对应做法：专业问答、项目精选、作品故事和更新说明统一使用编辑卡片，不让用户在首页面对多套组件语言。

#### 公共内容与个人上下文并置

参考站桌面端采用主内容 + 右栏。登录态右栏呈现个人足迹，游客态则使用注册价值说明、月历和工具箱，不展示零值个人仪表盘。它同时回答「站内正在发生什么」与「我现在可以去哪里」。

HseeHub 的对应做法：桌面端右栏提供最近看过、本周挑战和最近更新；无登录时用 localStorage，不显示空的个人数据仪表盘。

#### 高密度，但层级清楚

参考站信息很多，但依靠稳定字级、低对比边框、小面积类型色、统一元数据行和紧凑间距维持秩序。

HseeHub 的对应做法：保留克制工具感，但减少连续大标题、全宽分隔线和大表格。

### 4.2 明确不照搬

- 不复制品牌、配色、图标、文案、数据或像素布局；
- 不因为参考站有账号和社区，就提前建设登录、动态和评论；
- 没有真实活动与内容供给时，不造「最新动态」或零值仪表盘；
- 不把七个以上内容域同时放入一级导航；
- 不把 HseeHub 变成泛计算机学习平台。

## 5. 推荐信息架构

### 5.1 一级导航最多四项

| 导航 | 主要回答 | 对应现有内容 |
|---|---|---|
| 专业与课程 | 两个专业有什么共同点和不同任务？ | `/majors`、compare、curriculum |
| 做个项目 | 我现在能试什么、会产出什么？ | `/projects`、项目详情、资源页 |
| 能力地图 | 课程怎样变成可迁移能力？ | `/capabilities`，场景作为跨切面 |
| 选下一步 | 做过以后可以怎样继续？ | `/pathways`、explore、路径详情 |

首页品牌本身承担「开始」入口，不额外占一个导航项。

次级入口：

- 发展场景：从能力和项目页进入，不必与四个核心入口同权；
- FAQ：在首页、专业页和页尾露出；
- 来源与版本：作为信任中心放页尾和相关内容局部；
- About：页尾入口。

### 5.2 全站主线

```text
首页 / 开始
├─ 专业与课程
│  ├─ 两个专业对照
│  ├─ 同题双解
│  └─ 课程与能力
├─ 做个项目
│  ├─ 项目精选与筛选
│  ├─ 项目详情
│  └─ 资源、步骤与产物模板
├─ 能力地图
│  ├─ 能力详情
│  └─ 能力可迁移场景
└─ 选下一步
   ├─ 五类路径总览
   ├─ 未定方向双路径实验
   └─ 路径详情与证据转换
```

### 5.3 路由处置

- 保留现有路由，P0 不做破坏性迁移；
- 首页不再完整渲染五条路径和四档行动；
- `/pathways` 只承担五条路径的轻量比较：日常任务、15 分钟动作和一个关键门槛；
- `/pathways/[pathwaySlug]` 承担来源、资格边界和长周期行动；
- `/scenarios` 保留为可访问内容域，在能力与项目关系中稳定曝光；
- README、About、页尾、导航、metadata 和 sitemap 使用同一版产品定义。

## 6. 新首页详细规格

### 6.1 首页结构

```text
Sticky Header：品牌 + 4 个导航 + 主题切换

┌──────────────────────────── 主列 8/9 ───────────────────────┬── P1 右栏 4/3 ──┐
│ A. 今天想解决什么？                                        │ 最近看过           │
│ [看懂两个专业] [挑一个 90 分钟项目] [我还没想好]            │ 本周挑战           │
│ 首屏同时露出 1 张具体项目                                    │ 最近更新           │
├─────────────────────────────────────────────────────────────┴─────────────────┤
│ B. 这周可以做：3 张编辑精选项目                                                  │
│ C. 同一个问题，两种做法：1 个双专业协作案例                                     │
│ D. 做完能带去哪：1 个产物 → 2–3 个路径                                          │
│ E. 同学常问：4 个学生口吻、经语言评审的问题                                      │
│ F. 页尾：版本、来源、内容边界、About                                             │
└─────────────────────────────────────────────────────────────────────────────────┘
```

P0 可以只实现单主列；只有当真实更新内容和本地状态功能就绪时才加入右栏。390px 移动端全部单列，P1 右栏内容合并到主流并放在项目精选之后。

### 6.2 模块 A：任务启动台

目标：5 秒内让用户知道「这是帮助我看专业、做项目、找下一步的工具」。

推荐文案：

```text
今天想先弄明白什么？
不用一次决定未来。先看一个真实任务，或者动手试一次。

[看懂两个专业]
同一个问题，两边分别会做什么

[挑一个 90 分钟项目]
先看时长、基础和产出，再决定开始

[我还没想好]
同时试两条路，比较自己更愿意继续哪种任务
```

要求：

- 同屏最多 3 个同级任务入口；
- 只允许一个视觉主 CTA；
- 首屏必须同时露出一张具体内容卡，而不是只有入口说明；
- 桌面端关键内容应出现在距页面顶部 820 CSS px 内；
- 手机首屏在 844px 高度内看到站点用途、3 个入口和至少一个具体推荐的标题。

### 6.3 模块 B：这周可以做

首发陈列现有 3 个项目。每张卡的字段预算固定为「一句适合谁摘要 + 一句产物 + 3 个元数据」：

- 适合谁与会留下什么产物使用短句；
- 3 个元数据依次为总时长、最低基础、当前资源状态；
- 一个动作「看看怎么开始」。

卡面不重复数据许可、医疗免责声明、全部关系标签和所有来源。它们进入详情。

当前证据模型只登记 pathway endpoint，项目资源页仍有「待人工核验」硬编码。P0 必须新增 project 级 endpoint/link availability、owner 和最后检查时间，并把资源状态纳入关系校验，之后卡面才允许显示「可开始」。

聚合规则：主入口可用为「可开始」；主入口失效但替代入口可用为「有替代方案」；主入口与替代入口均不可用或未知为「暂不可开始」。每个项目至少登记一个主入口和一个可选替代入口。

### 6.4 模块 C：同一个问题，两种做法

首页只陈列一个双专业案例，结构为：

```text
一个可感知的工程问题
├─ 智能医学工程会先处理什么
├─ 生物医学工程会先处理什么
└─ 两边最终怎样接在一起
```

表达目标是让学生看到协作，不把两个专业写成互斥的「软件 vs 硬件」。

### 6.5 模块 D：做完能带去哪

首页只展示一个项目产物的迁移示例：

```text
一份可复核的项目记录
├─ 求职：问题、方案、结果、复盘
├─ 深造：研究问题、方法、证据和误差
└─ 独立项目：范围、交付、许可和边界
```

每条只展示一句「如何改写」和一个详情入口。资格、申请、录取或岗位要求默认折叠。

### 6.6 模块 E：同学常问

首发至少 4 个学生口吻的问题：

- 两个专业的区别真的只是软件和硬件吗？
- 我不确定方向，应该先补课还是先做项目？
- 项目做得很小，能不能算作品？
- 想考研、找工作或留学，现在做的东西能共用吗？

每个问题应映射到一个已验证 JTBD，并至少经过 3 名目标学生的语言评审。如果尚未完成访谈，必须标注「编辑部整理的常见问题」，不能把它称为真实学生原话或伪造学生引语。

### 6.7 右侧个人上下文（P1）

该模块不属于 P0 首页 A–F 的硬依赖。具备真实内容和状态能力后，可以加入：

- 最近看过：最近 3 条，localStorage 保存；
- 本周挑战：用户主动选择后显示，不预设任务；
- 最近更新：至少 3 条真实内容更新记录，不显示虚构活跃度。

无数据时隐藏对应块，不展示 0 天、0 项或空热力图。

## 7. 发展路径内容降载

### 7.1 保留什么

保留当前新增的：

- 五类路径；
- 每条路径的日常任务、已有资产、新增门槛；
- 15 分钟、7 天、30 天、一学期行动；
- 三类 artifact 与五类 evidence transformation；
- claims、endpoints、事实状态、链接状态、来源等级与复核时间。

这些是有价值的深层内容和可信基础设施。

### 7.2 首页只露出什么

- 三种开始方式；
- 一个产物迁移示例；
- 一个「看看几条可能的路」入口。

首页不再平铺五条路径的四列信息，也不渲染完整 5 × 4 行动阶梯。

### 7.3 `/pathways` 页面顺序

```text
你可能在想的几条路
→ 每条路平常真正做什么
→ 15 分钟先试一步
→ 一个最关键的新增门槛
→ 进入单条路径详情
```

`/pathways` 只比较日常任务、15 分钟动作和一个关键门槛，不承载完整四档行动、资格与来源长表。完整行动、资产转换、资格与来源全部进入 `[pathwaySlug]` 详情。不要先从资格边界、来源等级或完整比较矩阵开始。

### 7.4 路径详情页顺序

1. 这条路平时在解决什么问题；
2. 15 分钟能试什么；
3. 哪些已有课程或项目能复用；
4. 还要补什么；
5. 7 天 / 30 天 / 一学期行动；
6. 需要自己确认的资格与时效信息；
7. 来源和最后核验记录。

## 8. 内容模型与供给机制

### 8.1 统一内容层

当前 `site-data.json` 与 pathways/evidence 使用两套读取和校验方式。下一阶段应统一到同一 repository + Zod 模型，避免新旧内容关系继续分叉。

建议新增最小编辑内容类型：

| 类型 | 用途 | 最低上线数量 |
|---|---|---:|
| `featured_task` | 编辑精选小任务，不承诺每周更新 | 3 |
| `plain_guide` | 学生问句式短指南 | 4 |
| `artifact_story` | 一个作品怎样形成和改写，P1 | 0 |
| `update_note` | 最近更新了什么、为什么，P1 右栏启用条件 | 0 |
| `student_voice` | 经同意的学生经验，P1 | 0 |

### 8.2 统一基础字段

```ts
type EditorialContent = {
  id: string
  slug: string
  type: 'featured_task' | 'plain_guide' | 'artifact_story' | 'update_note' | 'student_voice'
  title: string
  deck: string
  audience: string[]
  timeCost?: string
  nextAction: { label: string; href: string }
  relatedMajorIds: string[]
  capabilityIds: string[]
  projectIds: string[]
  sourceIds: string[]
  provenance?: { kind: 'repository_commit' | 'editorial_record'; ref: string }
  author: string
  owner: string
  reviewer: string
  status: 'draft' | 'published' | 'stale' | 'archived'
  publishedAt: string
  updatedAt: string
  reviewDueAt: string
  visual?: {
    src: string
    alt: string
    kind: 'project_output' | 'process' | 'diagram'
    author: string
    license: string
    sourceRef: string
  }
}
```

外部事实内容必须有 `sourceIds`；纯内部更新说明可以使用 repository commit 或 editorial record 作为 provenance，但两者不能同时为空。`owner` 负责内容生命周期，`author` 负责创作，`reviewer` 负责事实复核，三者语义不得混用。

正式实现使用按 `status` 区分的判别联合：draft 可不填 `publishedAt`，published 必须具有全部发布日期和复核字段，stale/archived 保留历史日期但不得进入首页。`nextAction.href` 必须通过站内路径或 HTTPS 协议校验。

项目模型需补充 `stopCondition`、产物模板地址、模板版本、许可和复盘动作。当前 5 条 evidence transformation 全部集中在一个 artifact；Release A 必须保留这 5 条，并为另外两个项目 artifact 各补至少 2 条，校验每个首页项目均可映射到至少 2 条路径。

`student_voice` 额外要求：

- `consentStatus`；
- `anonymization`；
- 原始语境与编辑范围；
- 撤回机制。

### 8.3 首页内容门禁

- 所有首页陈列项必须有 owner、updatedAt、reviewDueAt；
- 过期项必须退出首页；在详情页保留时显式显示「需要复核」；
- 集合模块按配置的 `minItems` 决定是否展示：精选项目 3、FAQ 4、双专业案例 1、产物迁移 1、最近更新 3；
- 高风险陈述必须关联来源；
- 时间敏感的资格和报名信息只摘要，并链接到官方入口；
- 无授权不使用学生照片、姓名、原话或作品。

本站为静态/构建期架构，「自动退出」的实现是构建时按日期过滤，并由 CI 定时执行内容检查与重建；客户端时间不能作为唯一过滤机制。必选模块低于 `minItems` 时构建失败，可选模块才允许隐藏。

### 8.4 供给节奏

- Release A 首发：3 个项目、4 个常见问句、1 个双专业案例、1 个产物迁移示例；
- Release B：补 2 个作品故事、3 条更新说明并启用相应模块；
- 每两周：至少更新一个精选或作品故事；
- 每月：复核首页陈列；
- 每学期：复核培养方案、专业数据和路径入口；
- 每个内容模块必须有 owner 与过期策略。

先做编辑策展，再做投稿，最后才考虑社区。

## 9. 文案与语气规范

### 9.1 语气目标

像一位熟悉课程和项目的学长学姐：不夸张、不替你决定、把事实讲清楚，也愿意告诉你可以先试一点。

### 9.2 写作规则

- 先动作和结论，后术语与来源；
- 使用「你」「我们查到」「可以先试」；
- 不使用「我院」「学生应当」「务必选择」；
- 标题写真实问题或动作，不写栏目公文名；
- 一段只承担一个意思；
- 卡面最多一句摘要、三个关键字段、一个动作；
- 不用确定语气承诺升学、就业或资格结果。

### 9.3 建议替换

| 当前表达 | 建议界面表达 |
|---|---|
| 资格边界 | 先别急着下结论 |
| 不能证明什么 | 这一步还说明不了 |
| 官方入口与事实状态 | 要确认时去这里 |
| 登记核验 | 我们最后一次查到 |
| 五类主路径 | 你可能在想的几条路 |
| 新增门槛 | 通常还需要补什么 |
| 证据转换 | 把这份作品换一种说法 |
| 行动阶梯 | 从 15 分钟开始 |

### 9.4 禁用或慎用词

赋能、助力、高质量发展、全方位、权威解读、复合型人才、精准匹配、成功上岸、就业保障、同学们应当。

## 10. 视觉与布局规格

### 10.1 目标气质

```text
校园工具 + 编辑策展 + 工程可信度
```

不是招生专题页，不是政府门户，也不是通用 SaaS 仪表盘。

### 10.2 布局

- 1440px 桌面：首页采用 8+4 或 9+3 主列/侧栏；
- 内容最大宽度沿用现有约 1200px 基线，可小幅放宽但不超过 1280px；
- 长文详情阅读宽度保持约 760–820px；
- 768px 以下取消固定侧栏；
- 390px 与 320px 单列，无横向滚动；
- 表格仅在真正需要逐字段比较时使用。

### 10.3 首屏

- 当前超大标题降一级，避免一句话占据两到三行桌面空间；
- Hero 改为紧凑任务启动台；
- 首屏必须出现具体内容，不只出现抽象入口；
- 同屏同级选择不超过 4 个；
- 主 CTA 不超过 1 个。

### 10.4 组件语法

建议首页只使用四类基本单元：

1. `TaskEntry`：任务入口；
2. `EditorialCard`：项目、指南、作品故事统一卡；
3. `CompactList`：FAQ、更新、最近看过；
4. `EvidenceDisclosure`：来源、边界和核验详情。

避免每个内容域继续创造一套新卡片。

### 10.5 视觉素材

优先级：

1. 真实项目产物截图；
2. 设备、实验过程、手绘草图、数据图或结构图；
3. 经授权的校园空间与学习场景；
4. 必要时使用简洁的代码原生图示。

避免：

- 泛化 AI 科技插画；
- 假人物和摆拍式「未来医疗」图库；
- 仅作装饰、不解释内容的巨幅图片；
- 为模仿参考站而复制其图标和卡片细节。

首发即使没有人物照片，也必须至少有 3 个来自项目内容的真实视觉预览。

### 10.6 设计系统收口

- 保留现有亮暗主题与语义颜色 token；
- 统一圆角为小、中、大三档，首页不再新增特殊圆角；
- 类型色只用于小面积状态与识别，不做整屏彩色背景；
- 日期、数字和短标签可以使用统一 utility/等宽字体，正文与标题不滥用；
- 卡片 hover 位移不超过 2px、反馈时长控制在 150–180ms；普通列表行只改变浅底色；
- 减少全宽细线和每段都带编号眉题的模式；
- 将 `globals.css` 拆为 shell、shared components、content domains、pathways；
- 恢复 skip link 与 `<main id="main-content">`；
- 所有动画支持 `prefers-reduced-motion`。

## 12. 指标与埋点

### 12.1 北极星指标

P0 Meaningful Next Step Rate：同一匿名会话中按顺序完成以下合格序列的比例。

```text
project_detail_view
→ start_conditions_view
→ resource_open 或 artifact_template_open
```

事件需按会话去重，测试流量排除。P1 上线本地行动清单和意向标记后，再把 `action_plan_copy`、`try_intent_set` 纳入扩展指标。

### 12.2 核心漏斗

```text
首页任务入口曝光
→ 任务入口点击
→ 项目 / 专业 / 路径详情到达
→ 查看开始条件
→ 打开资源或产物模板
```

建议事件：

- `task_entry_view` / `task_entry_click`；
- `project_card_open`；
- `start_conditions_view`；
- `resource_open`；
- `artifact_template_open`；
- `source_open`。

P1 扩展事件：`action_plan_copy`、`try_intent_set`、`return_within_7d`。启用跨会话事件前必须确定匿名标识、保留期、Do Not Track/Cookie 策略和隐私说明；7 天产物完成情况仍以自报或访谈验证，不能用模板打开冒充完成。

不采集真实患者数据、项目私密内容或不必要身份信息。

### 12.3 体验指标

Release A 首发后先运行两周观察期建立新事件基线，第二个发布周期再判断相对提升，不拍脑袋设增长百分比。首发 P0 硬门槛：

- 8 名目标学生中至少 6 名在 5 分钟内找到适合的小项目；
- 至少 6 名能说清该项目会产出什么；
- 至少 6 名能用自己的话说出两个专业的一个共同点和一个差异；
- 至少 7 名不会把本站误认为官方资格判断工具；
- 5 秒测试中至少 6 名能说出「这是帮学生看专业、做项目、找下一步的探索站」。

### 12.4 信任护栏

- 高风险陈述 100% 关联来源与 `reviewDueAt`；
- 首页 0 条过期但无提示的内容；
- 0 个伪造学生引语；
- 时间敏感资格信息 100% 提供官方确认入口；
- 不以来源点击率低为由隐藏证据层。

高风险陈述的确定集合包括：学分、培养方案和课程归属；报名、资格和时效；录取、就业和结果性判断；医疗与安全；数据许可与隐私。以上内容必须进入 claim registry，普通编辑性引导不因语气自然而自动归为高风险事实。

完成条件：6/8 目标学生能说清站点用途并找到项目入口。

### Release A / Phase 2：首页、导航与项目闭环（估算 5–8 天）

- 路径完整内容下沉。

完成条件：首页与项目核心验收项通过。

### Release B / Phase 3：内容治理与个人上下文（估算 5–8 天）

- 通过兼容适配器按内容域迁移 schema/repository，禁止双写；只有所有页面、校验脚本和构建均切换后才退役旧读取层；
- 建立编辑内容类型与过期门禁；
- 接入 CI 定时内容检查与重建；
- 完成作品故事、最近更新和可选本地状态；

完成条件：新旧读取层没有双写，自动过期机制可复现，P1 模块只在有真实内容时出现。迁移失败可按内容域切回兼容适配器，不回退 Release A 的页面体验。

### Phase 4：验证与收口（估算 2–3 天）

- 目标学生可用性测试；
- 桌面/移动/暗色/200% 缩放回归；
- 性能与可访问性检查；
- README、About、Footer、metadata 收口；
- 建立视觉基线和发布检查单。

完成条件：本 Spec 第 13 节全部 P0 项通过。任何例外必须有风险说明、owner、审批人和到期日；没有审批的例外不能发布。

## 15. 风险与缓解

| 风险 | 表现 | 缓解 |
|---|---|---|
| 双受众冲突 | 新生看专业，高年级看方向，首页被拉成长页 | 按「今天要解决什么」分流，不混成单一线性叙事 |
| Pathways 继续扩张 | 首页和内容模型被五路径吞掉 | 路径固定为深层内容，P0 不新增类别 |
| 去官方化导致失真 | 为轻松而删掉来源或边界 | 采用行动层、理解层、证据层三层表达 |
| 内容快速过期 | 首页出现旧资格和旧入口 | owner + reviewDueAt + 首页过期门禁 |
| 缺少鲜活素材 | 页面仍只有文字、细线和表格 | 先补真实作品过程，不造学生故事 |
| 模仿变成换皮 | 复制参考站卡片与工作台外形 | 只迁移任务组织、统一信息流和上下文逻辑 |
| 工作区改动过大 | 产品重构与证据层混在一起难审查 | 先建回退基线，再按 Phase 分小提交 |
| 个人化空壳 | 无登录却出现零值足迹和热力图 | 无数据隐藏；先用有用的本地状态 |

## 16. 最终产品判断

HseeHub 的优势不是比学院官网多写一些课程，也不是比职业平台多列几条路径。它最独特的价值是把专业、能力、项目和下一步放进同一条可行动的链路：

```text
我看懂一种任务
→ 我亲手试了一次
→ 我留下了可以复核的东西
→ 我再决定是否继续
```

下一阶段的成功不应以新增多少页面衡量，而应首先以学生是否更快开始、是否能用自己的作品而不是网站口号理解自己来衡量；回访意愿作为上线后的观察指标。
